Featured project

SAT: Secure AI-Enhanced Telemetry

Feb to Jun 2026

View the repository on GitHubhttps://github.com/hafsa-mtm/sat-infra-configs

The problem

Edge sites produce logs and metrics that have to reach a central platform securely, be searchable in real time, and be checked for threats without someone reading every line.

The solution

An OpenStack cloud deployed with Ansible, a Kafka pipeline into Elasticsearch, a WireGuard tunnel from the edge, Wazuh for threat detection, and a Python model that flags unusual telemetry.

  • InfrastructureOpenStack 2024.2 (Nova, Neutron, Glance, Keystone, Heat) deployed with Kolla-Ansible and Docker Engine 29.4 on Ubuntu 22.04.
  • Telemetry pipelineFilebeat and Metricbeat on an edge gateway send logs and metrics through Kafka and Logstash into Elasticsearch 8.13. About 161,000 log documents and 73,000 metric documents were indexed.
  • SecurityWazuh SIEM 4.7 with an agent on the edge gateway, alerts indexed in Elasticsearch and shown in a MITRE ATT&CK view. WireGuard secures the link between edge and cloud.
  • Anomaly detectionIsolation Forest in scikit-learn on 10 features from logs, metrics and alerts. Scores are indexed for a Kibana dashboard and an anomaly triggers an email alert.
  • ObservabilityPrometheus 2.51 scraping Node Exporter and cAdvisor every 15 seconds, with Grafana 10.4 dashboards and four alert rules sent by email.
  • AutomationAnsible roles with Jinja2 templates and Docker Compose manifests, version-controlled on GitHub.

Built and tested in the lab

  • + Full OpenStack deployment, repeatable through Ansible
  • + Edge to cloud telemetry flowing end to end
  • + Encrypted tunnel with measured latency and loss
  • + Wazuh alerts indexed and searchable
  • + Dashboards and email alerting in Kibana and Grafana
  • + Anomaly model trained and evaluated

Still needed before production

  • > High availability for the control plane, Kafka and Elasticsearch
  • > Secrets management and TLS between every component
  • > Retention and capacity sizing from real traffic volumes
  • > Backup and disaster recovery procedures
  • > A CI pipeline that tests the Ansible roles

Experimental, not production-validatedThe anomaly model was evaluated on 1,000 records. That is enough to show the approach works and too small to call it a validated detector. A larger labelled dataset and drift monitoring would come next.
